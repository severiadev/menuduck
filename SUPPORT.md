# Feedback and support

[MenuDuck](README.md) · [Инструкция на русском](docs/ALPHA_GUIDE.ru.md)

English and Russian reports are welcome. You do not need to be a developer to report a problem.

## Bugs and ideas

Use [GitHub Issues](https://github.com/severiadev/menuduck/issues/new/choose) for non-sensitive bugs and suggestions. Search existing issues first and report one problem per issue.

A useful report includes:

- MenuDuck version and build, plus macOS version.
- Apple silicon or Intel; built-in/external display and notch, if relevant. No serial number is needed.
- What you did, what you expected, and what actually happened.
- Whether the issue repeats, and whether another menu-bar utility was running.

Attach a screenshot only if it helps, after checking it for personal information. Diagnostics are optional: review and redact them first. Raw logs can contain more than the visible error.

## Licenses, privacy, and security

Use the **private contact who invited you to the alpha** for activation limits, lost keys, data-deletion requests, or suspected security vulnerabilities. Do not post keys, tokens, private exploit details, or unredacted reports in GitHub Issues.

No public support mailbox is announced yet. If you have no private contact, you may open a non-sensitive issue asking the maintainer for a private contact route; include no secret or vulnerability details.

If macOS reports malware, a damaged application, or a checksum mismatch, stop installation and contact the organizer. Do not disable system security to continue.

## По-русски

Обычные ошибки и предложения можно описывать прямо в Issues на русском. Укажите версию приложения и macOS, действия и результат. Не присылайте серийный номер Mac.

Вопросы о лицензии, персональных данных и безопасности обсуждайте с организатором приватно. Не публикуйте ключи, токены, детали уязвимостей и диагностику без проверки. Публичная почта поддержки пока не объявлена.
